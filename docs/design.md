# EVE Wayfinder 最终产品设计：Gas 与 Hauling

版本：4；更新：2026-10-18。产品范围与验收边界已确认；本版加入保留 EVE 视觉风格的 UI 约束。这里只定义产品，不表示已经实现或验证盈利。

详细验收以 [产品规格](../.scratch/eve-assistant/spec.md) 为准；[讨论记录](../.scratch/eve-assistant/design.md) 保留决定来源。初始预算比例、路线跳数与启发式风险规则仍是透明、可调的产品参数，须经试用校准，不是实测事实。

## 产品目标

一个浏览器运行的单角色网页助手，自动读取角色信息、市场和公开风险数据，回答四个连续问题：现在能做什么；从零如何开始；下一步值得练什么、买什么；投入改变了哪些能力与收益条件。

首页两个入口：Gas Huffing 与 Arbitrage Hauling。用户选活动，助手自动生成方案；除授权、档位选择和可选 Gas 反馈外，不要求填写价格、技能、数量、产量等具体数字。游戏操作由玩家完成。

## 两个活动闭环

### Gas：入门 → 搜索巡回 → 收藏反馈 → 采集证据 → 成长

- 无船/无技能：根据角色给入门船装、缺件、训练路线、启动资金及首次搜索建议。
- 已有基础：从当前位置生成高安/低安巡回；短途/标准/长途，默认标准，支持返回固定出发地。
- 规划综合可采气体知识、市场价值、收藏、个人账本与风险；收藏是偏好，能因绕行或风险被跳过并解释。
- “收藏本星系”自动固定位置和时间，可多选见过的 Gas 类型，也可直接收藏。收藏、见过、实际采到是不同证据。
- 采集账本自动补充日期/星系/类型/数量；历史记录不等于当前存在气矿，缺记录不等于空扫。
- 理论连续采速、采集估值与实际销售分开；API 不提供精确采集分钟、现场余量或当前签名。

### Hauling：入门/当前/升级 → 货单 → 复核 → 运输 → 成交核对

- 无船也有完整入门路径：当前生效技能可用的模板、购置/装配现金、商品本金，以及准备好后可承接的货单。
- 当前资产可做、购置后可做、训练后可做三种状态并列；无资金或无机会时说明门槛，不能为了展示货单鼓励无依据购船。
- Hauling 提供高安、低安、00 三个独立开关，可任意组合；首次明确选择至少一项，之后记住选择，不预设玩家偏爱高安。“新手先从高安练习”只是入门建议，不覆盖所选区域。
- 开关同时约束采购地、出售地、采购前移动、运输与可选回程；关闭的区域不能被当作捷径。切换后重新规划并提示已有计划不再符合新范围，不修改真实持仓。当前位置不在范围或路线不连通时解释原因，不悄悄扩大范围。
- 区域选择独立于保守/均衡/激进模式；启用 00 不等于接受所有风险，启用多个区域也不强制每趟都经过它们。
- 交易仍只覆盖所选区域内的 NPC 空间站；00 中玩家建筑不纳入，数据覆盖不足或无适配船装时明确阻塞。00 船装与风险适配需单独验证，不直接套用高安/低安模板。
- 交易固定为吃来源卖单、运输、卖给目的已有买单；不把目的卖单价格当成可立即实现的收入。
- 首版默认一个采购站＋一个出售站，多种商品共用资金/容积/订单量；不因追求满仓而不断加停靠。
- 全旅程包含当前位置到采购地、必要停靠/装载、载货段、可选返程。回程可以空仓，不强迫凑单。
- 出发前复核关键报价，途中按缓存节奏发现变化。买单缩水则缩量并显示余货；买单消失则标失效并列可达 NPC 站即时出售备选，玩家决定，不自动挂单或改航。
- 对账依据实际交易/费用/损失。无法归属的费用、未知旧库存成本、未售持仓分别显示。

## 推荐卡应包含什么

| Gas | Hauling |
| --- | --- |
| 当前准备程度、建议船装 | 当前/购置/训练后的可用状态 |
| 巡回星系与收藏取舍 | 来源站、目的站、完整路线 |
| 可搜索 Gas 类别与证据年龄 | 商品数量、两端深度与价格 |
| 旅行估时及未知搜索耗时 | 船装投入、商品本金、费用准备 |
| 数据覆盖与风险背景 | 税后报价净利、利润率、利润密度 |
| 个人采集证据与升级入口 | 舱位/资金占用、机会时效、失效原因 |

所有结论可展开查看输入时间、来源、规则版本、假设与缺口。界面展示收益与风险取舍，不给虚假的单一“安全率”。

## UI：保留 EVE 视觉风格

用户明确要求保留 EVE 视觉风格。以下为本产品的视觉提案与交互约束，不声称精确复刻客户端或采用官方组件库。

### 视觉语言

- 深色石墨底、冷灰半透明面板、细分隔线和小圆角，呈现舰载终端的秩序感；避免大圆角卡片、装饰性霓虹和大面积发光。
- 主强调色为克制的冰蓝/青色，用于选中项、焦点和主要动作；盈亏、风险、警告和未知使用稳定的语义颜色，始终配文字/图标，不能只靠颜色判断。
- 初始色板建议：底色 `#080C11`、面板 `#141B24`、边框 `#2C3947`、正文 `#D8E1EA`、强调 `#70BDD6`。这些是起始设计值，最终以真实界面的对比度验证为准。
- 透明度与星图背景不能影响表格读数；默认数据区有足够不透明度，可关闭透明效果。装饰性星空集中在地图，不铺在所有文字背后。
- 紧凑、整齐的信息密度；金额、体积、时间和价格用等宽数字对齐，明确单位与精度。标题可用简短英文标签，中英正文使用清晰的系统字体回退，不牺牲中文可读性。

### 页面骨架

- 顶栏：角色、当前船、位置、钱包摘要、同步状态；窗口尺寸变化时保留关键上下文。
- 左侧窄导航：Gas、Hauling、成长、记录、设置；首页仍以两个活动入口为核心。
- 中部工作区：地图/路线与候选表格，支持查看商品/船装/升级详情；右侧可收起的证据抽屉展示所选方案的依据。
- Hauling 的高安/低安/00 以三个独立可切换控件并列，选中状态清楚；风险档位另组显示，不用相同分组混淆含义。
- Gas 顶部提供短途/标准/长途及“收藏本星系”；气体选择使用可跳过的小型浮层，不打断主流程。
- 成长视图使用当前→下一阶段的船装/技能比较，成本、属性变化、收益条件并排；能力解锁与效率升级有明确标签。
- 主要动作每个上下文保持突出，次要操作收敛到详情；空状态、无权限、同步中、过期和无可行方案都给下一步提示，不能用空表格代替原因。

### 可用性与验收

- 保留终端感，但正文、点击目标和焦点必须清楚；表格密度与界面缩放可调，支持键盘操作、清晰焦点与减少动态效果。
- 状态变化以局部高亮和短暂过渡提示；不使用持续闪烁或抢夺游戏焦点的提醒。
- UI 验收同时检查风格一致、文字对比度、长物品名/中文、金额对齐、选中/禁用状态，以及小窗口下查看方案和证据的能力。
- 风险色不是安全承诺；区域开关明确标注区域名称，数据陈旧与亏损也不能只通过色彩表达。

## 拟合与成长设计

- 审核模板＋角色适配＋属性校验；模板可以包含经当前版本验证的小件运输船，不只看工业运输船或最大容量。
- 依据生效技能判断现在能用，依据训练等级和队列规划学习；已有资产先去重并核实位置，远处资产不能当成瞬间可用。
- 计算容量、CPU/PG、槽位、对齐与关键能力，注明动态加成未知。资产快照有缓存，不能声称实时空余船舱。
- 模板绑定 SDE、计算器与参考验证版本。影响属性的更新发生后转为待复核，不能沿用旧性能标签。
- 效率升级：固定条件比较增量投入/增量收益，只有可信正分母才给回本小时/趟次。
- 能力解锁：解释新增活动与操作前提，如隐跳运输；不强行折成利润或生存概率。
- 购置现金、商品周转本金、已有资产替换价值和假设转售价分别列示。未卖旧装备，不提前把其估值当成可支配现金。

## 调研带来的关键增强

完整证据见 [开源工具研究](research/hauling-open-source-tools.md) 与 [Reddit 原帖研究](research/hauling-reddit-experience.md)。以下是综合推导出的产品决定，不是玩家收入的验证结果。

1. **按成交深度计算，再选数量**。现有工具展示了逐档成交和运力约束的重要性；任何商品都不能以顶层最好价格估整仓收益。最小成交量、买单范围、费用和共享预算必须在可行性检查内。
2. **机会有时效，填满船不是目标**。玩家报告绕路凑单错过主单，因此首版按同站点对组合，补充货物显示边际收益；不默认做多站多跳 beam search。
3. **完整旅行成本**。参考工具的空载移动、停靠与多趟计时，以及玩家回程问题，报告包含出发前移动和可选返程；多趟共享有限订单深度，后续趟次只是情景。
4. **失效后仍要有用**。已买货物的原买单消失后，展示余货和当前可达即时买家，分清“当时预计利润”与“现在可能实现的结果”，不悄悄改变策略。
5. **不把收益密度当万能排名**。同时展示总利润、资金效率、每立方米收益和旅行情景；预算、适配性、地域与风险始终是硬约束或明确成本项。
6. **新手不必先拥有大船**。小件、低体积商品与 NPC 商品可以进入研究候选，但必须有当前深度和税后机会；不硬编码固定商品、船型或利润承诺。
7. **旧经验按版本复核**。旧帖常见 Sunesis 两秒内起跳推荐，已受 2026 年船体变更影响；CCP 明确调整了货舱、质量与惯性。模板必须重算，不直接继承旧帖数字。[官方补丁](https://www.eveonline.com/news/view/patch-notes-version-23-02)
8. **费用由交易动作决定**。玩家评论常混淆直接成交与挂单；首版不把所有 broker 技能都当入门必要条件，不凭旧帖固定税率计算。[CCP 费用说明](https://support.eveonline.com/hc/en-us/articles/203218962-Broker-Fee-and-Sales-Tax)
9. **历史机会存续作为研究指标**。参考开源快照分析，用当时可见数据选货、按旅行时间情景看后来报价是否仍在；不能用未来数据选货。订单消失不证明成交，存续也不证明自己的成交。

## 实现与验收边界

React 网页 UI 通过同源 HTTP API 调用 Node 数据/推荐服务，服务端负责 SSO、凭据、缓存与限流。当前单用户本机实现使用加密凭据文件和 JSON 公开缓存；Python 研究能力和 SQLite 持久化可后续按需接入。token 不进入浏览器或日志。2026-10-18 用户决定由 Electron 改为网页应用。

主要验收：固定角色/市场/情报快照＋时钟＋策略 → 完整方案/成长报告/阻塞解释。少量 UI 端到端覆盖授权、模式/档位切换和收藏。真实 API smoke 独立执行；公开 schema 核验不是集成完成。

新增回归必须覆盖买单中途消失、只能卖部分持仓、重复使用订单深度、采购/返程遗漏、为凑满仓绕路、SDE 更新导致模板失效。

参考项目仅静态阅读，没有安装、执行或连接账号；参考方法不等于批准直接复制源码。MIT/GPL/许可不明分别评估，尤其拟合引擎/外部依赖的具体许可与打包方式须在选型时核查。

## 首版边界

单角色；Gas 高安/低安，Hauling 可选高安/低安/00 的即时运输套利。暂不做多角色、Ore anomaly、Gas 00、虫洞、玩家结构交易、courier 接单、market seeding、挂单套利、OCR、客户端控制、后台默认常驻或保证收益。

数据源以 [API 边界研究](research/character-api-boundaries.md) 和 [来源清单](research/activity-assistant-sources.md) 为依据。数据不可得时降级为条件结果或阻塞原因，不要求用户填写一长串数字来掩盖缺口。
