# EVE Wayfinder：Gas 与 Hauling 单角色活动助手

Status: ready-for-agent
Version: 5
Date: 2026-10-18
Review: 用户已确认规格与验收边界，并授权将开源工具与玩家经验调查纳入最终设计。

## Problem Statement

玩家想在 EVE 高安和低安采气，或在自己选择的高安、低安、00 区域运输套利，却需要在市场、地图、技能、拟合和击杀记录间反复切换。新手甚至没有合适的船，不知道启动资金、先练什么以及升级是否值得。现有信息容易把理想采速、显示价差和实际收入混为一谈。

玩家需要免填具体数字的建议：读取当前角色，说明现在能做什么、缺什么、去哪里，以及投资下一项技能或船装能改变什么。缺少现场 API 的信息应明确未知，而不是让玩家通过大量表单补齐。

## Solution

提供浏览器运行的网页助手。首版绑定一个角色，首页只有 Gas Huffing 和 Arbitrage Hauling 两个活动入口。登录授权后自动采集必要角色数据、市场、星图与风险背景，生成带来源时间和解释的活动方案。

Gas 提供高安/低安搜索巡回、当前星系收藏、可选 Gas 类型反馈、账本历史与从零入门路线。Hauling 在用户通过高安/低安/00 开关选择的区域内，寻找 NPC 站间立即买入、运输、立即出售的货单，结合角色技能推荐入门船装和升级选项。

两个模式共用成长建议，分效率升级与能力解锁。投资报告区分船装投资、货物本金、增量投入、情景收益及已实现收入；明确回本条件。游戏中的扫描、采集、交易与飞行由玩家完成。

## Implementation Decisions

### 1. 产品范围与数据可信度

- 单角色；不提供角色列表、切换或跨角色规划。
- Gas 地域仅限高安与低安。Hauling 提供高安、低安、00 独立开关，支持任意非空组合；首次选择后持久保存，不自动预选玩家偏好。两种模式均不经过虫洞。
- Hauling 区域开关同时约束候选采购地、出售地和全路线的每个星系，包括采购前移动与可选回程。禁用区域不能被当成捷径；当前位置不在范围或路径不连通时解释阻塞，不自动拓宽范围。
- 区域改变时重新生成候选；已选计划超出新范围则标记需重新确认，不静默改航、不修改实际持仓。开关全关闭时暂停规划并提示至少选一区域；启用多个区域仅是允许，不要求每条路线覆盖所有区域。
- Hauling 交易地点仅限 NPC 空间站；推荐前检查已知停靠限制。不能把 NPC 站标签当成任何角色均可进入的全面保证。
- 玩家只需授权、选择模式/档位/候选方案，以及可选收藏反馈；价格、数量、技能、钱包、位置等数值由数据服务读取或计算。
- 所有输出区分 API 观测、用户反馈、规则推算和未知。保留来源事件时间、抓取时间、有效期、覆盖与上游来源；同一击杀或同一市场上游不能被重复计权。
- 每份建议引用固定输入快照及计算策略版本。刷新不能悄悄修改玩家已选择方案的数量和资金安排；以失效状态和新版本提示替代。

### 2. 角色同步与数据接入

- 采用系统浏览器 SSO + PKCE；绑定角色 ID 并校验身份和已授权 scopes。仅请求活动需要的只读权限。无关邮件、日历等不采集。
- 基础数据包括位置、当前船、技能及队列、属性、植入体、资产、保存拟合、钱包/交易/流水、市场订单、采集账本、个人战损及必要 NPC 声望。
- 当前船实例与资产树关联以重建装备/货物快照；保存的拟合模板不得当成实际已装备状态。无法完整重建时标记不完整，并阻止依赖精确空余容积的执行声明。
- 当前可用装备看生效技能；训练缺口看已训练技能，并处理已完成但未反映到技能结果的队列条目。合并完成队列不自动假定对应等级目前生效。
- 现有队列优先采用服务端完成时间；新路线采用可追溯训练模型，注明账号状态/临时加成未知导致的条件差异。不得从单一字段宣称掌握 Omega 订阅与到期。
- 角色位置、资产、钱包交易等有不同缓存；按当前规格和响应头调度，尊重限流、Retry-After 和错误退避，禁止轮询绕过缓存。
- SDE 固定 build；ESI 固定已支持兼容日期。规格变更、SDE 升级和拟合模型升级均记录版本。
- 基础公共来源为官方星图/市场/系统活动与 zKillboard；社区市场历史等按实际需要扩充，不为“来源更多”重复采集同一上游。无明确生产接口或访问许可的来源只做链接，不成为必需依赖。

### 3. Gas 搜索与收藏

- 区域可采气体规则与站点知识是带来源/版本的知识库，不宣称由 ESI 给出实时刷点或出现概率。
- 规划使用当前位置、三档范围、气体可售价值、收藏、账本历史和风险背景；输出有意义的候选巡回、旅行估时及解释。旅行估时的船型和移动假设可查，搜索/采集耗时不计入确定值。
- 默认标准档。以下是本规格为实现提供的初始、可配置搜索边界，不是游戏事实或实测最佳值：短途最大单向星门距离 5 跳/总路线 12 跳，标准 10/24，长途 20/40；回程计入总路线。无可行路线时缩短或返回不足原因。
- 返回出发地为可选开关；路线结果显示是否包含回程。出发地固定于该次方案生成，不随位置更新漂移。
- 收藏使用最新有效位置观测；位置未知/过期时先同步，不猜测星系。写入时固定所显示的星系 ID 和观测时间，防止跃迁期间保存错星系。
- 收藏星系为唯一实体，多次点击不创建重复；Gas 观察按独立时间记录，多选类型并允许不选。操作在本应用保存，不调用游戏内书签。
- 收藏是软偏好；安全范围、路程预算和风险约束优先。手动取消收藏不抹除历史观察与账本证据。
- 用户见过、实际采到和收藏分别保存。旧观察随年龄降权，但收藏偏好不自动过期；账本没有记录不是“扫描未找到”，没有采到不是“已采空”。
- 账本按日期/星系/类型聚合，按键覆盖更新数量而非反复累加；本地持续保存，允许超过上游查询窗口的历史分析。日报不得冒充单趟记录。

### 4. Hauling 新手、货单与船装

- 无运输船时仍能生成明确的入门路径：当前生效技能可用的审核模板、缺件、可访问购置地点、完整购置现金、货物周转现金，以及购置/装配后才可执行的候选货单。
- 候选船不限定名称带“运输”的船型；当前版本下经过验证的小件运输模板也可入选。NPC 商品与消耗品仅是筛选类别，仍按当时订单验证；不承诺永远有某种盈利商品或安全货值。
- 新手路线可建议先在高安练习，但不预设或覆盖其高安/低安/00 选择。无经验历史不是新手身份的确定证据，界面提供“入门路线”入口。00 候选需验证对应船装/风险适配，不用其他区域的模板保证可行；覆盖不足或无适用模板时返回原因。
- 同时展示当前资产可用、需购置但技能已满足、需训练解锁三个状态；不会因没有船而显示空白。预算不足时说明最低可行门槛，不自动提高风险模式。
- 推荐基于有限、审核过的船装模板及允许的替换规则；为模板记录用途、必需技能、装备与槽位、性能假设、验证依据和版本。首版不动态穷举所有组合。
- SDE 或模型影响模板属性时，旧模板与性能结论转为待复核；未经重新验证不能继续宣称精确容量或对齐阈值。旧攻略的 Sunesis 等推荐不得跨版本沿用。
- 需要拟合计算模块计算容量、CPU/PG、对齐/航行相关属性和 Gas 理论采速。检查槽位、硬点、rig 规则、技能、可见植入体及必要适配约束；未校验的属性不得显示成精确结果。
- 入门/当前/升级拟合在相同条件下比较。隐跳等属于能力解锁，不直接推导生存概率或固定 ISK/h 加成；实际效果取决于玩家操作和场景。
- 按实例去重已有资产并保留位置，只有可访问且可调度的物品才计入可用库存；异地已有装备不是零成本瞬移，说明取回路径或直接购置方案。
- 船装购置现金、已有资产替换价值、货物本金与费用准备分别列示。投入是否可负担同时受现金和暴露约束；同一件已有模块不能分配给多个同时执行的方案。
- 货单仅采用来源卖单买入、目的买单出售；不假定未来挂单成交。执行估值检查剩余量、最小成交量、买单范围、实际交易地点与缓存完整性。
- 首版默认一份货单只有一个采购站和一个出售站，可组合多种商品；不为填满容量自动增加采购停靠。每项补充商品显示边际收益，组合受共同资金/容量/订单量约束。
- 按实际数量穿透订单深度，两端分别计算加权成交金额。组合货单联合约束预算、可用舱位与共享订单量；不能逐物品独立最大化后相加。
- 容积模型区分货舱与专用舱、物品资格及已占用容积，不把全船所有舱位相加作为通用空间。包装状态未知时使用兼容的保守体积，不能凭空压缩/打包已有物品。
- 区域 history 只能作区域流动性背景，不证明某站成交。未知成本标记未知或明确估计；成本无法给出合理上界时不声称已确认净利为正。
- 报价净利润为目标数量的卖出收入减买入成本、预计交易税及适用的明确费用；首次船装购置单列，不对每趟重复扣全额。没有待实现挂单时不虚加挂单 broker fee。
- 船装采购与货物采购可能来自不同地点；无有效采购深度或费用信息时输出条件方案，不显示“现在可执行”。执行前刷新过期的关键报价。
- 完整估时包括当前位置到采购地、采购/装载停靠、载货航段及可选回程；已知已有货物避免重复采购。多趟情景必须扣减共享订单深度并包含中间返程，不能把第一趟利润乘以趟数；后续趟次明确为条件情景。
- 货单同时显示总报价净利、利润率、每立方米净利、实际预计跳数与旅行时间情景；时间不足以支持可靠分母时不宣称精确 ISK/h。任何单指标排序均不能越过资金、船装、地域和风险约束。
- 购买前复核，途中按各数据源缓存节奏监测机会变化。目的买单缩水时重新计算可售数量及剩余库存，消失时列其他可达 NPC 站的即时出售备选；买入后成本按实际已知成本，不沿用旧采购估值。
- 替代方案由玩家选择；禁止静默改数量/改航或把未成交余量自动转成挂单策略。无即时卖出路径时明确持仓未实现与可能损失，不填零成本或假定原买单回归。

### 5. 风险与预算规则

- 保守/均衡/激进是可解释策略，不是测量出的安全概率；默认保守。高安/低安/00 区域选择与风险模式独立，不能因切换模式自动改变地域，也不能把启用 00 理解为无限风险容忍。
- 以下为规格补充的初始可配置默认值，后续按实际使用调整：新增现金投入上限分别为可用现金的 10%/20%/30%；单趟船装替换价值加货物价值的暴露上限分别为可用现金的 20%/35%/50%。这不是从 API 读取的玩家风险偏好。
- 可用现金从最新钱包扣除本应用已选择方案的资金预留和可确认的其他承诺；未选择的候选只是假设，不相互预留。ESI 钱包已排除的 escrow 不再次扣除。无法确认时保守标记。
- 新增现金上限同时覆盖尚需购买的船装、货物本金与显式费用准备。已有船仍按替换价值纳入暴露；超限时不给“可执行”标记，但可展示未来目标和门槛。
- 风险依据包括事件时间、数据年龄、近期船/蛋击杀、交通背景及猎人活动；系统活动汇总与 killmail 明细存在重叠，不简单相加。缺数据不视作零风险。
- 初始风险评分是带版本的可解释启发式，不是统计损失率。路径成本同时包含旅行与风险项；保守档对风险/未知的惩罚不得低于均衡，均衡不得低于激进。具体权重连同固定输入输出验收样例一起版本化，输出分项而非伪概率。
- 无可行方案时如实说明资金、技能、范围、深度、风险或数据缺口，不降低约束凑结果。

### 6. 成长建议与投资报告

- 两种模式都提供技能前置图、训练顺序、船装阶梯及投入报告。已有技能、资产和队列去重；当前条件不足的方案属于目标，不是可立即执行推荐。
- 效率升级显示前后属性、增量购置现金和假设；能力解锁说明新增场景、代价与限制，不强行折成收入。
- 收益对比必须固定相同市场快照、技能/加成假设、工作量或活动条件；每次只改变所比较升级及其必要前置，避免把价格变化算成装备收益。
- Gas 分开报告理论连续采集价值、有限站点/损耗影响、运输变化与整趟估计；无法观察搜索时间与实际有效采集分钟时，不给“你的实测 ISK/h”。
- Hauling 比较同一批机会与条件下的可装载数量、报价利润及预计旅行差异；容量增加不代表一定有更多可成交深度。
- 正增量收益下才计算回本条件。增量收益为零/负数，或缺少可信单位时间/趟次分母时，显示“无法据此回本/数据不足”及原因。技能训练时间单列，不未经同意折成购买注入器的现金成本。
- 区分购置现金、已有资产机会成本、可转售价情景和净经济成本；未实际卖出旧装备时，回本现金预算不提前抵扣其估值。
- 个人化历史须给出样本数量、覆盖期间和局限。首版不以不足样本提供校准损失概率；无充足证据时保留理论与敏感性场景。
- 钱包/订单/战损按稳定 ID 去重；销售收入不等于利润，采集估值不等于销售。费用无法归属、旧库存成本未知、损失与货单关联不明确时单列，不能强行配对。

### 7. 应用与模块边界

- UI 保留 EVE 风格：深色石墨底、冷灰半透明面板、细边框、紧凑表格、克制冷色强调和等宽数字。采用可读的中英文字体，提供清晰焦点、语义文字与可调密度；视觉起始值不是官方客户端参数。
- 页面由角色状态顶栏、窄导航、地图/候选工作区和可收起证据详情构成；区域开关与风险档位独立分组。透明度、动画和背景不影响数据辨认，提醒不抢夺游戏焦点。
- React 网页承载 UI，通过同源 HTTP API 连接 Node 服务；后端负责身份、凭据、缓存和 worker 生命周期。首版在本机以单用户运行；未来公开站点需独立的用户会话和数据隔离。Python 分析及 SQLite 持久化按后续需求接入。
- 浏览器仅通过有输入/来源校验的窄 HTTP API 调用服务；前端不取得 token 或直接访问文件系统。SSO 使用独立浏览器标签页，凭据在服务端加密存储，日志和导出不含 token。
- 对外应用服务集中提供角色状态、生成方案、保存/取消收藏、查看成长报告及同步状态。核心验收从“给定带时钟的角色/市场/情报快照和活动选择，返回方案/阻塞理由/成长报告”切入；不暴露内部评分与表结构给 UI。
- 数据模型涵盖角色快照、物品实例与位置关系、市场订单快照、采集聚合、Gas 收藏及观察、拟合模板、路线、活动方案、资金预留、策略版本和费用/收入记录。
- 收藏的星系唯一键、账本聚合键、killmail/transaction ID 和快照完整性是显式不变量。私有数据与公共缓存区分，数据库迁移保留历史，网络失败不覆盖最后成功快照。
- 已有相邻项目的 ESI 缓存、SSO、账本与费用分析可在核对许可和接口后复用；首版不引入客户端控制链或 OCR。LLM 不是路线、拟合、估值或资金计算的必需依赖。
- 关闭应用会停止本地 worker；不默认安装后台服务。打开应用后可恢复历史与同步，离线显示年龄和失效状态。

## Testing Decisions

- 主验收边界为应用服务：注入固定角色、市场、情报、时钟和策略，检查用户可见完整方案、约束、解释和阻塞原因。验证行为，不逐项复制内部公式，不对私有函数和 UI 样式做镜像测试。
- 核心场景：无船新手、已有船/缺件、生效与训练等级不同、完成队列未同步、余额不足、快照不完整、市场深度不足、无可行路线。每个失败应返回明确原因，不返回假装可执行的货单。
- Gas：收藏幂等、多 Gas 类型、不选类型、跃迁时位置绑定、取消收藏保留证据；收藏可因硬约束跳过且说明；旧采集记录不变成当前矿点，账本重复同步不重复计量。
- 路线：全路径地域约束、三档跳数上限、可选回程、固定出发地、断开图、风险数据缺失、重复击杀去重。验收同输入/时钟/版本结果确定。
- Hauling 区域：覆盖三开关全部八种组合（全关无方案）、选择持久化、仅高安时禁止低安捷径、允许 00 但不要求每趟经过、采购前移动/回程遵守开关、起点在禁用区、区域切换使旧计划失效，以及区域与风险档位不互相改写。
- Hauling：跨多档价格深度、最小成交量/范围、共享订单和资金、专用舱、缺失实际空余空间、船装购置消耗现金、已有船替换暴露、候选不重复预留、计划过期。
- 拟合采用审核后的独立参考结果验证首批船装，覆盖生效技能、槽位、CPU/PG、容量和关键能力；参考来源/模型版本明确，不能只对比同一计算器生成的“预期值”。
- 成长：零/负增量收益不返回回本数；固定市场下升级对比；估值与成交分开；未知旧库存成本/无法归属费用不得变成零成本已实现利润。
- 适配器合同检查覆盖分页完整性、缓存/限流、授权缺失、身份不匹配、重复同步、部分失败保留成功快照与凭据脱敏。OAuth 回调及 IPC 需验证状态/来源与输入。
- 少量浏览器端到端检查覆盖无授权到首个可用方案、Gas 收藏、活动/风险档位切换、离线恢复。大部分边界场景在应用服务层完成，避免重复脆弱 UI 测试。
- UI 视觉验收覆盖 EVE 风格一致、长名称/中文、数字与单位、对比度、键盘焦点、开关/禁用/过期状态、小窗口和减少动态效果；状态不能只靠颜色表达，不对具体样式实现写镜像测试。
- 新增回放场景：主要买单抵达前消失、容量填满但绕路更差、返程计入后效率下降、买单深度只能覆盖第一趟、SDE 变更使旧模板属性失效、仅部分持仓可即时出售。断言原方案失效及替代方案，不验证内部优化器细节。
- 离线机会存续研究严格使用当时可见快照选货，按旅行时间情景检查之后报价深度；缺失历史快照标缺口。买单消失不证明被成交，后来仍有买单也不证明个人实际可成交，此研究不是收益回测的替代。
- 当前仓库没有产品测试先例，只有公开规格调查脚本；相邻研究项目可借鉴固定数据驱动的分析验证，但必须重新验证本产品行为。真实 ESI/SSO smoke 是授权环境下的独立集成验证，不能由公开 schema 验证代替。

## Out of Scope

- 多角色添加/切换/资金与资产联合规划。
- Ore anomaly、Gas 00、虫洞与动态虫洞链；Hauling 00 已纳入区域选择范围。
- 玩家建筑交易、私有地图与联盟跳桥整合。
- 等待成交的挂单套利、自动下单、自动飞行/采集/装卸、鼠标键盘控制。
- OCR、截图、客户端日志或剪贴板后台采集；Gas 主动收藏反馈除外。
- 实时气矿签名/余量、全量 local 或实时猎人追踪；把缺少记录当成安全证明。
- 精确单趟采集耗时、保证利润、校准过的个人死亡概率、完整账户订阅与临时加成推断。
- 全装备组合自动拟合优化、多平台全面验证、发布分发和默认后台常驻采集。
